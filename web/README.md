# Trial2Voice web app (Track A prototype)

Frontend-only prototype: everything runs in the browser, with no server code. Plan: [../docs/build-plan.md](../docs/build-plan.md). Spec changes: [../docs/prd-addendum-v1.1.md](../docs/prd-addendum-v1.1.md).

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npx vitest run     # unit tests, including validation of the demo scripts
```

## Phase 1 — Script (done)

- **Ingest** an NCT ID straight from the ClinicalTrials.gov API v2 (`src/lib/ctgov.ts`).
- **Bullet splitter** turns registry text into inclusion / exclusion bullets (`src/lib/bullets.ts`).
- **Script builder** calls Claude (Sonnet 5.5) from the browser with your own API key, using structured JSON output and server-side refusal fallback (`src/lib/script/builder.ts`, prompt in `prompt.ts`).
- **Age and sex rows** are generated by code, never by the LLM (`src/lib/script/derived.ts`).
- **Validator** blocks approval on uncovered bullets, non-quoted source text, missing Spanish or caregiver wording, rule/answer mismatches, and the word "eligible" in caller-facing text (`src/lib/script/validate.ts`).
- **Editor**: registry text beside the criteria, groups, glossary, call settings and version diff (`src/components/script/`).
- **Approval lock**: approver, IRB reference and date, plus a SHA-256 fingerprint. Locked versions can't be edited.
- **Audit log**: every change is chained by hash (`src/lib/store/repo.ts`).
- **Protocol-change watch** runs when the Trials page opens. A changed registry record marks the script stale and pauses calls. "Simulate registry change" demos this.
- **Demo trials** (MODIUS, OBOE, MOTION-P) ship with pre-built scripts written to the same rules, so no key is needed (`src/data/demo/`).

## Phase 2 — Call (done)

Open a locked trial and click **Start a test call** (or go to `/call/<NCT ID>`).

- **Decision engine** (`src/lib/engine.ts`): the only code that sets eligibility. A lint rule blocks any LLM import. A screen-out counts only after a confirmed read-back; anything unclear becomes "Needs site review".
- **Call flow** (`src/lib/call/session.ts`): disclosure → consent → who's calling → questions → read-backs → closing review → contact → close (Addendum G5). It also handles repeat, clarify (approved alternates, then the glossary), go back, medical questions, asking for a person, caregiver switch, under-18 stop, silence and the 12-minute cap.
- **Red flags** (`src/lib/call/redflags.ts`): checked on every caller turn in English and Spanish. Self-harm stops the call at once. Other categories ask "Is this happening right now?"
- **Answer parsing**: a built-in keyword parser (`parse.ts`) needs no key. With a key, Claude Haiku 5.5 reads answers (`llmInterpreter.ts`) and falls back to the keyword parser on any error.
- **Voice**: browser speech in Chrome and Safari (`src/lib/voice/webspeech.ts`), with typing always available. A spoken filler plays when understanding takes longer than 700 ms.
- **Privacy**: no transcript is kept without consent or for under-18 callers. Contact details are read back but never stored, and the name and phone digits are redacted in the saved transcript.
- **Tests**: 30 end-to-end call scenarios in `session.test.ts`, alongside the parser, red-flag, phone and engine tests. 502 tests in total.

## Phase 3 — Referral, coordinator, quality (done)

- **Referral queue** (`/coordinator`): tabs for To review, Held for quality review, Not a match (for sampling missed eligible callers), Red flags, Follow-up and Closed.
- **Referral page** (`/coordinator/referrals/<id>`): every answer traced to its question, the caller's words and the result. The header reads like "14 of 14 asked criteria passed · 35 to confirm at site". It also shows the nearest site, the demo contact line, voicemail and best-time preferences, and the caregiver-permission banner. Coordinators can accept, or reject with a reason. They can override any answer, and the outcome is re-scored by the same engine, or override the status itself with a reason. Contact attempts are logged, with "unreachable" after 3, and a voicemail is blocked if the caller said no. Every action goes into the audit log. The page is printable.
- **Call console** (`/coordinator/calls/<id>`): the transcript with timestamps, every agent step with its timing, latency figures for understanding answers, and flagged turns highlighted.
- **Post-call judge** (`src/lib/quality/judge.ts`): rule checks always run. They flag any agent line not found in the approved script, a missing disclosure, any mention of "eligible", questions asked before consent, a screen-out without a confirmed read-back, and "you" wording on caregiver calls. With an API key, Claude Sonnet 5.5 also reviews for advice and off-script claims. Flagged calls are held until a person releases them.
- **English ↔ Spanish** switching turn by turn (`src/lib/call/language.ts`), keeping the current question.
- **Nearest site** from the caller's ZIP code (`src/lib/sites.ts`). The closing line names the site, and the ZIP itself is never stored.
- **Embeddable widget**: `<script src="/embed.js" data-trial="NCT…">` adds an iframe pointing at `/embed/<NCT ID>`. The test page is `/embed-test.html`.

## Phase 4 — Evals, insights, ship (done)

- **Simulated callers** (`src/lib/evals/`): 20 personas per trial, generated from the script, each with known ground truth. A responder replies to whatever the agent actually says. `evals.test.ts` runs all 60 for the demo trials in `vitest run` and asserts the PRD §9 gates plus the G10/G11 gates. A failing gate fails CI.
- **Evals page** (`/evals`): runs the same callers in the browser against each trial's latest version, drafts included, with either the keyword parser or Claude. It shows the gate table and each caller's transcript, saves the run, and compares it with the previous one.
- **Insights page** (`/insights`): the funnel from page opened to visit scheduled, drop-off by criterion, and the PRD §3 and G11 metrics, from this browser's data.
- **Export / import** (Settings → Data): a JSON backup of every table, with no API keys. Replace or merge, with the audit chain verified after import.
- **CI** (`.github/workflows/ci.yml`): lint, type-check, tests including the eval gates, and a production build.

## Site-provided voices

ElevenLabs voices come from the site, not the visitor. `src/app/api/tts` and `src/app/api/voices` are the only server code. They read `ELEVENLABS_API_KEY` from the environment (see `.env.example`) and proxy to ElevenLabs, with these guards: same-site only, a text length cap, an optional voice allowlist and a per-IP rate limit (`src/lib/server/elevenlabs.ts`). Visitors bring only their own Claude key.

Data lives in this browser's IndexedDB. Track B swaps `src/lib/store` for Postgres behind API routes.
