# Trial2Voice web app (Track A prototype)

Frontend-only prototype: everything runs in the browser, with no server code. Plan: [../docs/build-plan.md](../docs/build-plan.md). Spec changes: [../docs/prd-addendum-v1.1.md](../docs/prd-addendum-v1.1.md).

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npx vitest run     # unit tests, including validation of the demo scripts
```

## Phase 1 — Script (done)

- **Ingest** an NCT ID straight from the ClinicalTrials.gov API v2 (`src/lib/ctgov.ts`).
- **Bullet splitter** turns registry text into inclusion / exclusion bullets (`src/lib/bullets.ts`).
- **Script builder** calls Claude (Sonnet 5.5) from the browser with your own API key, using structured JSON output and server-side refusal fallback (`src/lib/script/builder.ts`, prompt in `prompt.ts`).
- **Age and sex rows** are generated by code, never by the LLM (`src/lib/script/derived.ts`).
- **Validator** blocks approval on uncovered bullets, non-quoted source text, missing Spanish or caregiver wording, rule/answer mismatches, and the word "eligible" in caller-facing text (`src/lib/script/validate.ts`).
- **Editor**: registry text beside the criteria, groups, glossary, call settings and version diff (`src/components/script/`).
- **Approval lock**: approver, IRB reference and date, plus a SHA-256 fingerprint. Locked versions can't be edited.
- **Audit log**: every change is chained by hash (`src/lib/store/repo.ts`).
- **Protocol-change watch** runs when the Trials page opens. A changed registry record marks the script stale and pauses calls. "Simulate registry change" demos this.
- **Demo trials** (MODIUS, OBOE, MOTION-P) ship with pre-built scripts written to the same rules, so no key is needed (`src/data/demo/`).

Data lives in this browser's IndexedDB. Track B swaps `src/lib/store` for Postgres behind API routes.
